# 家庭位置地图与食物到期提醒需求设计

## 背景

家里经常会买常温食品、零食、囤货和部分冰箱食材。真正容易被遗忘的不是每天打开的冰箱，而是零食柜、囤货柜、箱子、抽屉、餐边柜等低频查看位置。用户希望先做一个网页，后续迁移到微信小程序，帮助家庭成员知道家里有什么、放在哪里、什么时候前需要吃完或处理。

第一版产品不是传统库存系统，也不是自动识别所有物品所在位置的视觉系统。它的核心是：

- 用家庭小组共享一套食物库存。
- 用自定义位置地图记录家里真实的柜子、箱子、抽屉和冰箱区域。
- 通过语音录入、拍日期识别和手动修正，降低长辈录入负担。
- 通过快到期列表和按位置筛选，快速知道什么该处理。
- 通过一键标记拿走、吃完、丢弃，让家庭成员共同维护库存。

## 产品定位

项目暂定名：家里还有啥。

目标用户：

- 主要用户：妈妈，需要低学习成本、少打字、少看日期。
- 辅助用户：家庭成员，可以录入、查看、标记拿走或用完。
- 管理用户：创建家庭小组的人，负责邀请成员、维护位置和修正识别结果。

第一版成功标准：

- 买完东西后愿意录入。
- 录入一个普通物品不超过 20 秒。
- 打开首页 3 秒内知道哪些东西快到期。
- 可以按具体柜子或箱子查看里面有什么。
- 家庭成员拿走或吃完后愿意点一下标记。
- 常温食品和囤货过期浪费明显减少。

## 设计原则

1. 位置地图是记忆辅助，不做自动归属判断。
   柜子照片和卡通封面只用于帮助用户识别位置。系统不根据照片猜测某个食物放在哪个柜子。

2. 食物归属必须明确。
   每个物品都必须通过手动选择、语音说明或确认页选择，明确归属于某个存放位置。

3. AI 结果必须可确认、可修正。
   语音识别、日期识别、图片识别都只能生成待确认内容，不能悄悄入库。

4. 第一版优先解决真实高频痛点。
   先做好家庭位置、语音录入、拍日期、快到期筛选和一键标记。小票识别、多商品批量识别、菜谱推荐等能力后续迭代。

5. 为小程序迁移预留能力。
   网页第一版以应用内提醒为主，但数据结构保留提醒规则和提醒记录，方便后续接微信订阅消息。

## 用户角色

### 家庭管理员

通常是创建项目的人。可以：

- 创建家庭小组。
- 邀请家庭成员。
- 创建、编辑、删除存放位置。
- 修改食物信息。
- 查看操作记录。

### 家庭成员

可以：

- 查看全部食物和快到期食物。
- 按位置筛选食物。
- 添加食物。
- 标记拿走、吃完、丢弃。
- 修改自己录入的内容。

第一版可以不做复杂权限控制。家庭管理员和普通成员的差异主要体现在小组管理与位置管理上。

## 核心对象

### 家庭小组

字段：

- 家庭小组 ID
- 家庭名称
- 成员列表
- 创建人
- 创建时间

### 家庭成员

字段：

- 成员 ID
- 昵称
- 头像
- 角色：管理员、成员
- 加入时间

### 存放位置

位置是独立对象，不是食品分类。它表示家里真实存在的存放空间。

示例：

- 妈妈零食柜
- 阳台囤货箱
- 餐边柜第二层
- 电视柜下面
- 冰箱冷冻左抽屉

字段：

- 位置 ID
- 家庭小组 ID
- 位置名称
- 原始照片
- 卡通或简笔画封面
- 可选标签：常温、冷藏、冷冻、零食、囤货、药品
- 备注
- 是否常用
- 排序
- 创建人
- 创建时间

位置照片和卡通封面的目的：

- 让长辈更容易确认这是哪个柜子或箱子。
- 让位置地图更直观。
- 避免完全依赖抽象命名。

### 食物

第一版以食品和可食用囤货为主，但数据结构不写死，后续可以扩展到日用品或药品。

字段：

- 食物 ID
- 家庭小组 ID
- 名称
- 数量
- 单位
- 到期日
- 存放位置 ID
- 保质期或日期照片
- 状态：在库、已拿走、已吃完、已丢弃、已过期
- 录入来源：手动、语音、拍日期
- 创建人
- 最后操作人
- 备注
- 创建时间
- 更新时间

### 操作记录

用于解决家庭协作中的信息不透明问题。

字段：

- 记录 ID
- 操作人
- 操作类型：新增、编辑、拿走、吃完、丢弃、移动位置、修改日期
- 关联食物
- 变更前内容
- 变更后内容
- 操作时间

示例：

- 妈妈标记蛋黄派已拿走 1 包。
- 爸爸标记牛奶已喝完。
- 管理员把坚果礼盒移动到阳台囤货箱。

## 信息架构

第一版主导航包含：

- 快到期
- 位置地图
- 添加
- 记录
- 我的家庭

### 快到期

默认首页。回答“现在最该处理什么”。

分组：

- 已过期
- 今天到期
- 3 天内到期
- 7 天内到期
- 30 天内到期
- 长保质期但即将到期

支持筛选：

- 全部位置
- 单个具体位置
- 常温
- 冷藏
- 冷冻
- 已过期
- 本周到期
- 30 天内到期

食物卡片显示：

- 食物名称
- 剩余天数
- 到期日
- 数量和单位
- 存放位置
- 快捷操作：我拿了、吃完了、丢弃、编辑

### 位置地图

回答“家里哪个柜子里有什么”。

列表展示每个位置：

- 卡通或简笔画封面
- 位置名称
- 当前在库数量
- 最近到期的食物
- 是否存在过期或快到期食物

位置详情页：

- 默认按到期日排序。
- 支持按名称、录入时间排序。
- 支持查看该位置全部食物。
- 支持只看该位置的快到期食物。
- 支持食物移动到其他位置。
- 支持一键拿走、吃完、丢弃。

## 核心流程

### 创建家庭小组

1. 用户创建家庭小组。
2. 输入家庭名称。
3. 生成邀请入口。
4. 家庭成员加入后设置昵称。

### 创建存放位置

1. 点击添加位置。
2. 输入或语音说位置名称。
3. 拍一张柜子、箱子或抽屉照片。
4. 系统生成卡通或简笔画封面。
5. 用户确认封面和名称。
6. 保存位置。

如果卡通封面生成失败，仍保留原始照片，位置可以正常使用。

### 语音录入食物

示例语音：

“零食柜有三包蛋黄派，8 月 20 号到期。”

系统解析：

- 名称：蛋黄派
- 数量：3
- 单位：包
- 位置：零食柜
- 到期日：8 月 20 日

确认页规则：

- 已识别字段直接填入。
- 未识别字段提示补充。
- 位置必须明确，不能自动猜。
- 用户保存前可以修改所有字段。

如果语音没有说明位置：

- 显示位置选择器。
- 默认高亮最近使用的位置。

如果语音没有说明日期：

- 提供拍日期和手动选日期两种补充方式。

### 拍日期识别食物

适合用户不想看生产日期、保质期、有效期的场景。

流程：

1. 用户选择拍日期添加。
2. 拍包装上的生产日期、保质期或有效期。
3. 系统识别日期信息。
4. 如果识别到有效期，直接填到期日。
5. 如果识别到生产日期和保质期，计算到期日。
6. 进入确认页，用户补充名称、数量、位置。

日期识别结果必须显示置信提示。识别不确定时，要求用户确认或手动选择。

### 手动添加食物

用于 AI 识别失败、临时补录或用户主动精确录入。

必填：

- 名称
- 到期日
- 位置

选填：

- 数量
- 单位
- 备注
- 日期照片

### 标记拿走、吃完、丢弃

食物卡片和详情页都提供快捷操作。

我拿了：

- 可选择数量。
- 数量减少。
- 数量归零时，状态变为已拿走或已吃完，由用户确认。

吃完了：

- 默认处理全部数量。
- 状态变为已吃完。

丢弃：

- 状态变为已丢弃。
- 可选原因：过期、坏了、不想要、其他。

所有操作都进入操作记录。

## 提醒规则

网页第一版只做应用内提醒：

- 首页显示快到期数量。
- 已过期置顶。
- 不同紧急程度使用明显颜色和文案。
- 打开应用后默认进入快到期页。

默认提醒分级：

- 已过期：红色，置顶，直到处理。
- 今天到期：红色。
- 3 天内：橙色。
- 7 天内：黄色。
- 30 天内：普通提醒。

默认提前提醒规则：

- 保质期 7 天内：提前 1 天进入重点提醒。
- 保质期 30 天内：提前 3 天进入重点提醒。
- 保质期超过 30 天：提前 7 天进入重点提醒。

小程序阶段再接入：

- 微信订阅消息。
- 可选择提醒成员。
- 可配置提醒时间。
- 可配置提前天数。

## MVP 范围

第一版包含：

- 家庭小组。
- 家庭成员。
- 自定义存放位置。
- 位置照片。
- 位置卡通或简笔画封面。
- 语音录入食物。
- 拍日期识别。
- 手动添加和修正。
- 食物明确归属于某个位置。
- 全部快到期列表。

## 非功能需求

### 易用性

- 移动端优先。
- 大字、大按钮、少字段。
- 关键流程尽量控制在 3 步内。
- AI 结果统一进入确认页。
- 位置选择必须明显，不能藏在高级设置里。

### 数据可靠性

- 食物入库前必须经过用户确认。
- 到期日为空的食物不能保存为有效库存。
- 位置为空的食物不能保存为有效库存。
- 所有状态变更记录操作人和时间。

### 可迁移性

- 前端先做网页，但界面和流程按小程序习惯设计。
- 业务数据不依赖浏览器本地状态。
- 提醒规则和提醒记录独立建模，方便后续接微信订阅消息。

## 已确认约束与可调整项

当前已确认：

- 第一版采用家庭位置地图方案。
- 柜子地图只辅助定义和识别位置，不自动判断食物归属。
- 食物通过语音、拍日期、手动修正录入，并明确归属于某个位置。
- 首页需要能看全部快到期，也能按具体位置筛选。
- 提醒第一版先做应用内提醒，后续迁移小程序后接微信订阅消息。

后续实现前可以继续调整：

- 是否需要单独的“药品”标签。
- 到期提醒的默认提前天数。
- 是否需要给长保质期食品设置更早提醒。
- 家庭成员是否允许删除位置和食物。
